# Temporal / Turn Grounding Guard

**時刻・直近の会話順序・永続記憶の操作証拠を照合し、検出した不整合を修正してから返答を送るための小さなPythonパッケージです。**

朝の出勤を告げた会話に古い就寝挨拶が混ざる、実際には隣接していない発言を「直後」と説明する、実行証拠がないのに永続記憶を保存したと言う、といった限定的な日本語パターンを扱います。

## 返答へ反映する流れ

1. 送信前の候補を、時刻・発言の原文・実行receiptと照合。
2. 不整合があれば、呼出し元のモデルへ最大1回の修正を依頼。
3. 修正後の文を、同じ証拠とreceiptでもう一度照合。
4. 修正できなければ `blocked` と `reply=None` を返し、候補を送出しない。

アプリ側では、**`result.reply` が存在するときだけ表示・送信します。** 候補のストリーミングや先行表示をすると、この送出条件を通らない表示が発生します。修正処理のあとに過去ログや正準記憶を書き換える処理はありません。

## 導入

Python 3.11以上。実行時の外部依存なし。

```bash
git clone https://github.com/GaikichiAtaoka/turn-grounding-guard.git
cd turn-grounding-guard
python -m pip install .
python -m unittest discover -s tests -v
python examples/agent_integration.py
turn-grounding-guard --input examples/synthetic_input.json
```

統合サンプルは、合成会話を使って `pass / corrected / blocked` の3経路を実行します。修正役は固定のテスト用コールバックです。検出結果が最終表示へ反映される配線を確認する例で、実モデルの正答率を示すものではありません。

CLIの合成入力は意図的な不整合を含みます。`blocked / reply=null / 終了コード2` が期待結果です。終了コード0は送出可能、1は入力不正です。

**[既存AIアプリへの詳しい組み込み手順](docs/INTEGRATION_JA.md)** には、候補を保持する位置、モデルへの修正依頼、再検出、送出を止める分岐、実行receiptの作成例をまとめています。

## 公開範囲

| 項目 | 内容 |
|---|---|
| 時刻との照合 | 明示された出勤意向と、朝の返答に混ざった就寝挨拶 |
| 会話順序 | 実際の隣接発言と「直後に返した」という説明 |
| 実行証拠 | 当該ターンの成功した記憶保存・更新と、完了を主張する文章 |
| 返答の修正 | 最大1回のテキスト修正、その再検出、未修正候補の送出停止 |

途中送信検知、一般的な記憶検索、内省、本体ランタイムはこの公開物に含みません。

## 入力と境界

現在時刻と過去発言の日時にはUTCオフセットが必要です。現在時刻に指定したタイムゾーンの4:00〜11:59を朝の判定に使います。朝だからという理由だけでは就寝挨拶を止めません。夜勤後の帰宅や明示的な休息希望を考慮します。

直近3時間を対象とし、出勤意向は90分で朝判定への適用を終えます。日時がない記録や未来の記録を補完せず、省略件数を返します。発言順の照合では、省略された行を挟んだ発言を隣接扱いしません。本文を途中で切り取って意味を変えないため、容量を超えた入力はエラーにします。

実行receiptはアプリの実行器が作成してください。モデルの「保存しました」という文章をreceiptに変換してはいけません。`turn_id`・操作種別・厳密な成功真偽値を照合し、別ターン、読取りだけの操作、失敗を保存の証拠へ流用しません。

## 検出の限界

日本語の一部の表現を対象としたルールです。未検出や誤検出は起こり得ます。`pass` は、このルールが対応する不整合を見つけなかったことを意味します。回答全体の正しさや、あらゆる日時・人物・出来事の照合を保証するものではありません。

修正役のモデルにも同じ限界があります。**検出済みの問題が再検出でも残る場合は、返答を送出できる結果にしません。** モデルコールバック内部のツール無効化、保存無効化、タイムアウトは呼出し元が設定します。
